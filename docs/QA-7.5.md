# 7.5 풍선톡톡 및 가로 화면 검수

2026-10-27, Windows의 격리된 Playwright Chromium/WebKit에서 검수했습니다. 기준은 원격 main `e3ac6ed`(7.4.2), 작업 브랜치는 `feat/balloon-tap-landscape`입니다. 기존 PC 체크아웃을 변경하지 않고 별도 복제본에서 작업했습니다. 운영 배포·병합·원격 푸시는 하지 않았습니다.

## 검수한 메뉴와 하위 활동

- 홈 `home`, 더 많은 놀이 `more`, 생각 놀이터 `think`.
- 투명 엘리베이터 `elevator`, 화장실 탐험대 `potty`, 블록팡 `blockpang`, 풍선톡톡 `balloon`.
- 말글 `language`(한글·자음·모음·단어), 가나다 리듬 `hangul`, 영어 찾기 `english`, ABC `alphabet`, 그림 영단어 `englishWords`·그림 한글단어 `koreanWords`(각 10개 분류).
- 숫자 놀이 `numbers`, 숫자 기차 `numberBoard`, 수량 `quantity`, 순서 `numberOrder`, 손가락 `finger`.
- 도형 `shape`, 색깔 `color`, 기억 `memory`, 함께하기 `together`, 보물상자 `treasure`, 음악 `music`.
- 역할놀이 `village`: 마트·주방·동물병원, 장보기 8개·요리 3개·환자 3개 경우.
- 퍼즐 `puzzle` 12개, 마음친구 `feelings` 12개 상황, 진정 놀이 3개와 완료 상태.
- 보호자 PIN 진입·설정·앱 안내·PIN 변경·기록·초기화 확인, 휴식 안내, 블록/풍선 일시정지.

## 수정한 배치

- 홈: 낮은 가로 화면에서 콘텐츠를 잘라내지 않고 스크롤합니다. 태블릿 가로에서 추천 카드와 인사말이 겹치지 않도록 배치했습니다.
- 블록팡·퍼즐: 낮은 가로 화면에서는 판과 조각을 옆으로 놓아 드래그 시작점과 도착점을 함께 볼 수 있습니다.
- 역할놀이: 마트 품목과 장바구니, 요리 재료와 조리대, 환자와 도구를 낮은 높이에 맞게 배치했습니다.
- 엘리베이터: 낮은 가로 화면에서는 20개 층 버튼을 4열로 놓고 문 버튼을 분리했습니다.
- 화장실: 장면과 단계 카드를 나란히 놓습니다. 감정·모달·보호자 메뉴는 필요한 스크롤을 허용합니다.
- 음악: WebKit 태블릿 세로에서 발생한 카드의 최소 너비 넘침을 수정했습니다.
- 풍선: CSS 풍선과 영상·손 표시의 좌표계를 맞추고, 회전 시 캔버스 크기만 갱신해 진행 상태를 유지합니다.

## 재현

Node.js 22 이상에서 다음 명령을 사용합니다.

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium webkit
pnpm test
pnpm lint
pnpm build:offline
pnpm test:layout
pnpm test:balloon:browser
pnpm test:rotation
pnpm test:offline
# 인터넷이 필요한 공식 모델 확인. 카메라는 사용하지 않습니다.
pnpm test:model
pnpm dev
```

로컬 주소는 `http://127.0.0.1:4173/#balloon`입니다. 실행만 할 때는 패키지 설치 없이 `node scripts/serve.cjs`도 가능합니다. 각 브라우저 검사는 테스트 서버를 자동으로 시작하고 종료합니다. `QA_ENGINE=chromium` 또는 `webkit`, `QA_SIZE=667x375` 환경 변수로 전체 화면 검사를 좁힐 수 있습니다.

원시 결과는 `.test-results/landscape/results.json`, 전체 스크린샷과 필터 갤러리는 `.test-results/landscape/index.html`, 신규 기능 결과는 `.test-results/balloon/*.json`에 있습니다. `.test-results`는 Git에서 제외됩니다. 대표 증거는 [screenshots/7.5](screenshots/7.5)에 보관했습니다.

## 실제 기기에서 남은 확인

배포 승인 후 Y700 사용 계획에 맞춰 Chromium **1280×800, 1024×640**에서 같은 전체 라우트·하위 상태 검사를 추가했고 **220건 통과, 실패 0건**입니다. 풍선 터치·모의 카메라 흐름은 1280×800 → 800×1280 → 1024×640 회전으로 재검사했습니다. 블록·퍼즐·화장실 드래그 중 회전도 이 크기에서 Chromium/WebKit 각각 통과했습니다. `QA_SIZE=1280x800` 또는 `1024x640`으로 화면 검사를, `QA_TABLET=1`로 풍선·회전 검사를 재현할 수 있습니다. 이는 Y700의 실제 CSS 크기나 성능을 가정한 실기기 검사가 아닙니다.

기존 `android-kiosk` 래퍼는 Manifest에 `INTERNET`만 선언하고 기본 `WebChromeClient`를 사용합니다. `CAMERA` 선언, Android 런타임 권한 요청과 WebView `onPermissionRequest` 처리가 없으므로 해당 APK의 카메라 지원은 확인되지 않았고 현재 코드로 허용되지 않습니다. 권한을 확대하지 않았습니다. 카메라 몸놀이는 우선 Android Chrome에서 HTTPS 운영 주소를 열고, 최초 `카메라로 시작` 때 카메라 권한을 허용하는 경로로 확인해야 합니다. 카메라를 사용하지 않으면 손가락 모드를 선택할 수 있습니다.

**사용자 카메라를 켜거나 촬영하지 않았습니다.** 손 동작·권한·리소스 해제는 모의 입력이며, 실제 모델 검사는 인물이 없는 생성 캔버스입니다. 실제 아이의 손 인식, 조명·거리·가림, 저사양 발열/속도, iPhone Safari의 카메라와 설치 PWA·홈 복귀, 실제 노치 safe area는 별도 실기기 확인이 필요합니다. Windows WebKit 검사를 실제 iPhone Safari 검사로 간주하지 않습니다.

기존 게임과 풍선 터치 모드는 앱 오프라인 캐시로 검사했습니다. **새 카메라 모델의 완전한 오프라인 실행은 보장하지 않습니다.** 모델/런타임은 카메라 시작 후에만 별도로 받아 기존 게임의 서비스워커 설치를 막지 않으며, 다운로드 실패 시 손가락 모드를 제공합니다. 자세한 출처와 개인정보 처리 범위는 [BALLOON.md](BALLOON.md)에 있습니다.
